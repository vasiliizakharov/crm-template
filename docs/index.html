Service CRM

Руководство пользователя и администратора. Система управления сервисным центром: заказы-наряды, склад, финансы, зарплата.

Содержание: Обзор · Вход · Роли · Заказы · Клиенты · Склад · Финансы · Зарплата · Отчёты · API · Развёртывание · Операции

1. Обзор

Service CRM Template — open-source web system for a network of service centers. Implements core service-center processes: intake, order status flow, parts inventory, per-order finance, master salary calculation.

Веб-интерфейс: https://crm.example.com · API: https://crm.example.com/api/ · API docs: https://crm.example.com/api/docs

Технологии

  • Backend: FastAPI (Python 3.12)
  • Frontend: React 18 + Vite + Tailwind
  • DB: PostgreSQL 16
  • Auth: JWT (HS256, 7 дней)
  • Метрики: Prometheus /metrics

Контейнеры

  • service-crm-db — PostgreSQL
  • service-crm-backend — FastAPI
  • service-crm-frontend — статика SPA на nginx

2. Вход в систему

  1. Открыть https://crm.example.com в браузере (Chrome/Firefox/Safari).
  2. Ввести email и пароль администратора (выданы при установке).
  3. После входа открывается Дашборд со сводкой за 30 дней.

Сессия живёт 7 дней. После истечения система перенаправит на форму входа автоматически.

4. Заказы (Заказ-наряд)

Создание заказа

  1. Раздел Заказы → + Новый заказ.
  2. Выбрать клиента из справочника (или сначала создать в разделе Клиенты).
  3. Указать заявленную неисправность и предварительную стоимость.
  4. После создания открыть карточку заказа и добавить позиции (запчасти/услуги).

Жизненный цикл (FSM статусов)

new → diagnosing → awaiting → in_repair → ready → issued → warranty
                                          ↑                ↓
                                          └──── (cancelled из любого, кроме issued) ──┘
СтатусКогда выставлять
newЗаказ принят, ждёт диагностики
diagnosingМастер диагностирует устройство
awaitingОжидание запчастей или согласования с клиентом
in_repairИдёт ремонт
readyГотов к выдаче
issuedВыдан клиенту. Автоматически проставляется issued_at и гарантия +90 дней.
warrantyВозврат по гарантии
cancelledОтмена

Состав заказа

В карточке заказа кнопка + Позиция добавляет:

  • Услугу — название, кол-во, цена, % мастеру (для расчёта зарплаты).
  • Запчасть — выбор из каталога; остаток автоматически списывается со склада. При удалении позиции — возвращается на склад.
Если на складе недостаточно запчастей — добавление позиции не пройдёт. Сначала оформите приход на склад.

Приём оплаты

Кнопка Принять оплату в карточке заказа создаёт финансовую транзакцию income с привязкой к заказу. paid_amount и payment_status заказа обновляются автоматически (unpaid → partial → paid).

История

Каждое изменение статуса, редактирование и оплата фиксируются в разделе История карточки заказа. Хранится JSON-снимок «было/стало» и комментарий.

5. Клиенты

Раздел Клиенты: справочник физических и юридических лиц. Поиск по имени/телефону/email. Поля: ФИО, телефон, доп. телефон, email, ИНН, адрес, заметки, скидка %, blacklist.

Удаление клиента запрещено, если у него есть заказы (RESTRICT FK). В этом случае пометьте его в blacklist.

6. Склад

Каталог

Раздел Товары: позиции типа part (запчасть, есть остаток на складе) или service (услуга, не имеет остатка). SKU, цена клиента, себестоимость.

Движения

ТипДействие
inПриход (закупка / поступление)
outРасход (расходование, уход в заказ выполняется автоматически)
adjustУстановить остаток в заданное значение (инвентаризация)
writeoffСписание (брак, потеря)

Любое движение фиксируется в журнале stock_movements с user_id, временной меткой и комментарием.

7. Финансы

Все денежные операции — в одном журнале transactions с двумя типами:

  • income — поступление (оплата заказа, прочие доходы)
  • expense — расход (выплата ЗП, аренда, закупка запчастей, прочее)

Методы оплаты: cash card transfer sbp other.

Каждая транзакция МОЖЕТ быть привязана к заказу (FK order_id). Операционные расходы (аренда, коммуналка) идут с order_id = NULL.

На дашборде раздела показаны три карточки: Доходы, Расходы, Баланс (income − expense) за весь период.

8. Зарплата

Правила начисления

Для каждого сотрудника создаются правила (Зарплата → + Правило) с компонентами:

ПараметрНазначение
base_salaryФиксированный оклад за период
work_share_pct% от стоимости работ (для мастера). Может быть переопределён на уровне позиции order_items.master_share_pct.
parts_share_pct% от наценки на запчасть (price − cost) × qty (для мастера)
revenue_share_pct% от общей выручки заказа (для менеджера)

Расчёт

В разделе Зарплата → Рассчитать выбирается сотрудник, период и опциональные премии/удержания. Кнопка Предпросмотр возвращает расчёт без сохранения, Сохранить — фиксирует в salary_records.

Алгоритм для одного заказа из периода (включаются только заказы с issued_at ∈ [start; end)):

сотрудник = master_id заказа?  для каждого item:
    if item.kind = 'service':
        works += unit_price * qty * (item.master_share_pct ИЛИ rule.work_share_pct) / 100
    if item.kind = 'part':
        margin = max(0, (unit_price - unit_cost) * qty)
        parts  += margin * rule.parts_share_pct / 100

сотрудник = manager_id заказа?
    revenue += order.total_amount * rule.revenue_share_pct / 100

ИТОГО = base_salary + works + parts + revenue + bonus - deduction

Выплата

В таблице сохранённых расчётов кнопка Выплатить ставит paid=true и автоматически создаёт расходную транзакцию категории salary на сумму ИТОГО.

11. Развёртывание (для админа)

Требования

  • Docker 24+ и Docker Compose v2
  • Внутри Proxmox LXC: features: nesting=1,keyctl=1 в /etc/pve/lxc/<id>.conf
  • Свободный порт 127.0.0.1:8090 (backend) и 127.0.0.1:8091 (frontend)
  • Reverse-proxy (nginx) на 80/443 с прокидыванием на эти порты

Установка

# 1. Клонировать или распаковать исходники в /srv/service-crm/
# 2. Настроить переменные окружения:
cp .env.example .env
nano .env   # PG_PASSWORD, JWT_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD

# 3. Собрать и запустить
docker compose up -d --build

# 4. Проверить:
curl http://127.0.0.1:8090/health
curl -I http://127.0.0.1:8091/

Структура переменных .env

ПеременнаяНазначение
PG_PASSWORDПароль PostgreSQL для пользователя crm
JWT_SECRET64-символьный hex для подписи токенов (HMAC-SHA256)
ADMIN_EMAILEmail первого администратора (создаётся идемпотентно)
ADMIN_PASSWORDПароль первого администратора
ADMIN_FULL_NAMEФИО для отображения

Резервная копия и восстановление

# Бэкап (запускать ежедневно через cron)
cd /srv/service-crm && make backup

# Восстановление из дампа
gunzip -c backups/crm_YYYYMMDD_HHMMSS.sql.gz | \
  docker compose exec -T db psql -U crm -d crm
Хранить бэкапы за пределами того же сервера. Минимум — другая машина в той же сети, оптимум — внешнее S3-совместимое хранилище.

Обновление

# 1. Получить новый код (git pull / scp)
# 2. Пересобрать и перезапустить
docker compose up -d --build
# Миграции применяются автоматически при старте backend (idempotent).

Мониторинг

Endpoint /metrics отдаёт метрики в формате Prometheus:

  • service_crm_requests_total{method,path,status} — счётчик запросов
  • service_crm_request_latency_seconds{method,path} — гистограмма задержек
  • service_crm_orders_total{status} — текущее распределение заказов по статусам
